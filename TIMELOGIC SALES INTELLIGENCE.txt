# TIMELOGIC — SALES INTELLIGENCE & BUSINESS ANALYTICS MODULE

You are working on the existing **TimeLogic** desktop Admin application.

I want you to add a completely new module to the Admin application that allows an organization to upload its sales records and automatically turn those records into a professional business intelligence dashboard.

The feature should feel like something a professional **data analyst / business intelligence system** would provide, not simply a spreadsheet viewer.

---

## 1. NEW ADMIN SCREEN

Create a new Admin navigation item/screen.

Use a professional name such as:

**Business Analytics**

or

**Sales Intelligence**

Choose whichever fits the existing TimeLogic UI/branding best.

This screen becomes the organization's central location for uploading, analyzing, and viewing historical sales data.

---

# 2. FILE UPLOAD SYSTEM

The organization should be able to upload sales records from different file formats.

At minimum support:

* `.xlsx`
* `.xls`
* `.csv`
* `.sqlite`
* `.db`
* `.json`

Design the import system so that additional formats can be supported later.

The user should be able to click:

**Upload Sales Data**

and select their file.

Do NOT assume every organization uses the same spreadsheet structure.

For example, one company may have:

```text
Date | Product | Quantity | Price | Total
```

Another may have:

```text
Transaction Date | Item Name | Units Sold | Unit Price | Revenue
```

Another may have:

```text
date
product_name
qty
amount
```

The system should intelligently detect and map columns.

---

# 3. DATA IMPORT / COLUMN MAPPING

After uploading a file, inspect its structure.

Automatically identify likely fields such as:

* Date
* Product
* Product ID/SKU
* Quantity
* Unit Price
* Revenue/Sales Amount
* Cost
* Profit
* Customer
* Salesperson
* Category
* Invoice/Transaction ID

If the system cannot confidently identify a column, show the administrator a simple mapping interface.

Example:

```text
YOUR FILE

Transaction Date   →  Date
Item Name          →  Product
Units Sold         →  Quantity
Selling Price      →  Unit Price
Amount             →  Revenue
```

Allow the administrator to correct the mapping before importing.

Do not destroy the original uploaded data.

---

# 4. MONTHLY DATA MODEL

The most important requirement is that sales data must be organized by month.

For every imported record, determine:

* Date
* Month
* Year

Example:

```text

March 2026
April 2026
...
```

The organization can upload sales records covering up to **31 days for a month**.

For example:

```text

```

The system should recognize that these records belong to January.

When February records are later uploaded:

```text
February 1 → February 28
```

they must be stored separately from January.

Do NOT overwrite January.

The system should continuously build historical business records.

Example:

```text

February
March
```

# 5. PREVENT DUPLICATE IMPORTS

The system must protect the organization's historical data.

If an administrator uploads the same sales file twice, do not blindly duplicate every transaction.

Implement duplicate detection using appropriate identifiers such as:

* Transaction ID
* Invoice ID
* Date + Product + Quantity + Amount
* File hash
* Other reliable unique combinations

If duplicates are detected, clearly tell the administrator.

Example:

```text
Import completed

1,245 records detected
1,210 new records imported
35 duplicate records skipped
```

# 13. PROFITABILITY ANALYSIS

If the data contains:

```text
Selling Price
Cost Price
Quantity
```

calculate:

```text
Profit per unit
Total profit
Profit margin
```

Formula:

```text
Profit = Revenue - Cost
```

and:

```text
Profit Margin = Profit / Revenue × 100
```

Show:

```text
Highest Margin Products
Lowest Margin Products
Highest Total Profit Products
```

Clearly distinguish:

**Profit margin**

from

**Total profit**

because a product with the highest margin may not generate the highest total profit.

# 26. IMPORTANT BUSINESS LOGIC

The system must understand that:

**Revenue ≠ Profit**

If the organization only provides:

```text
Date
Product
Quantity
Selling Price
```

the system can calculate:

```text
Revenue
```

but cannot accurately calculate profit unless cost information exists.

Therefore show:

```text
Profit data unavailable

Your uploaded file does not contain product cost information.
Upload cost data to enable profitability analysis.
```

Do NOT estimate profit unless the organization explicitly provides a cost/expense methodology.
